# 展开明细卡死修复方案

## Context

用户反馈：查看扫描结果时，点击选中某条命中"展开明细"界面直接卡死无响应。

根因（已逐一核实）：`ScanController.detailHitsModel` 是一个 QML 直接绑定的 `@Property`（notify=`selectedResultChanged`），被 [ResultDetailPanel.qml](file:///f:/Dev/fuscan/src/fuscan/gui/views/components/ResultDetailPanel.qml#L239) 的 `Repeater.model` 绑定。用户点击选中结果 → [setSelectedResultIndex](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L931-L936) emit `selectedResultChanged` → QML 在**主线程同步**重新求值 `detailHitsModel` → [build_detail_hits_model](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/_result_detail.py#L93-L127) 对 `result.hits` 逐条调 [_extract_context](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/_result_detail.py#L48-L90) → **每条命中都同步 `path.read_text`（最多 1MB）+ `splitlines` + 逐行 `in` 搜索**。命中无数量上限，同一文件的多条命中重复读盘、重复分行、重复搜索，主线程串行执行 O(命中数 × 文件行数)，导致界面冻结。压缩包内部条目走 `hit.detail` 兜底不读文件，不受影响。

预期结果：点击选中任何结果，明细区**立即**显示（规则名/严重度/匹配文本/描述先出），文件上下文由后台线程补齐，主线程绝不因读文件阻塞——即使超大文件或海量命中也不卡。

修复力度：用户已批准「主线程优化 + 异步 worker」组合方案。

## 措施 A：主线程优化（重构 `_result_detail.py`）

保持 `build_detail_hits_model` 公共签名不变（作 `build_detail_hits_full` 的等价别名，兼容 QML 与现有测试），新增两个纯函数与一个批处理内部函数：

1. **`build_detail_hits_light(result) -> list[dict[str, object]]`**：纯内存，不读文件。逐条产出与现有**完全相同的键集**（`ruleName/severityText/severityColor/context/matchText/matchCount/target/description`），`context` 直接取 `hit.detail` 占位。主线程瞬时完成。

2. **`build_detail_hits_full(result) -> list[dict[str, object]]`**：完整构建（供后台 worker 调用）。压缩包条目等价 light（不读文件）；非压缩包走批处理定位。

3. **`_extract_contexts_batch(path, match_texts) -> dict[str, str]`**：同一文件**只读一次、只 `splitlines` 一次**，一遍 `enumerate(lines)` 定位所有 match_text 首个命中行：
   - 复用现有前置守卫（`exists` → `stat().st_size > _MAX_CONTEXT_FILE_SIZE` → `is_text_file` → `read_text`），只做一次；任一失败返回空 dict（调用方回退 detail）。
   - `pending = {mt for mt in match_texts if mt}`（去空去重）；一遍扫描，每行检查 `pending` 快照中哪些 `mt in line`，命中即记录首个行号并移出 `pending`，`pending` 空则提前 `break`。
   - 对每个已定位 `mt` 用现有 `_CONTEXT_LINES` 窗口切片生成带 `>>> ` 标记的 context。
   - 复杂度从 O(命中数 × 行数) 降到 O(行数)，读盘/分行从「每命中一次」降到「每文件一次」。
   - `_extract_context` 保留为薄封装 `_extract_contexts_batch(path, [match_text]).get(match_text, "")`，改动最小。

4. **下调 `_MAX_CONTEXT_FILE_SIZE` 1MB → 256KB**：context 只取前后各 2 行，超 256KB 的文本文件多为日志/数据转储，读全文收益低。现有 1.5MB 超限用例仍通过，新增 300KB 用例锁定新阈值。

## 措施 B：异步 worker（新增 `detail_worker.py`）

新建 [detail_worker.py](file:///f:/Dev/fuscan/src/fuscan/gui/workers/detail_worker.py)，照搬 `FilterWorker` 形态：

```python
class DetailWorker(QThread):
    done = Signal(list, int)  # (完整 detail model, 世代号)

    def __init__(self, result: ScanResult | None, generation: int) -> None:
        super().__init__()
        self._result = result
        self._generation = generation

    def run(self) -> None:
        model = build_detail_hits_full(self._result)
        self.done.emit(model, self._generation)
```

- `run()` 纯调纯函数 + emit，无事件循环依赖，可同步单测（满足 Windows 约束）。
- `done` 携带 `generation`，主线程回调按世代号丢弃过期结果。
- [workers/\_\_init\_\_.py](file:///f:/Dev/fuscan/src/fuscan/gui/workers/__init__.py) 的 `__all__` 与导入追加 `DetailWorker`。

## 措施 C：ScanController 集成（[scan_controller.py](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py)）

- **顶层导入** `from fuscan.gui.workers.detail_worker import DetailWorker`（detail_worker 不反向依赖 controller，无循环依赖，且便于测试 monkeypatch 注入，与 `FileStatsWorker` 一致）。
- 新增成员：`_detail_worker: DetailWorker | None = None`、`_detail_generation: int = 0`、`_detail_hits_model: list[dict[str, object]] = []`。
- 新增信号 `detailHitsModelChanged = Signal()`。**用独立信号而非复用 `selectedResultChanged`**：worker 完成后只需 QML 重求 `detailHitsModel`（Repeater.model），不应连带触发 `detailFilePath/detailHitsCount/detailFileSize/detailIsArchiveEntry/canReplaceSelected` 等其余绑 `selectedResultChanged` 的属性重算；语义上「详情就绪」与「选中变化」是两件事，独立信号无信号环。
- `detailHitsModel` 属性改为 `notify=detailHitsModelChanged`，getter 直接返回 `self._detail_hits_model`（不再在 getter 内读文件）。
- 新增 `_refresh_detail_hits()`：`_cancel_detail_worker()` → `_detail_generation += 1` → 取选中 result。
  - `None` → model=`[]`，emit。
  - 压缩包条目 → 主线程同步 `build_detail_hits_full`（不读文件），emit，跳过 worker。
  - 正常 → 先 `build_detail_hits_light` 填缓存 + emit（UI 立即出规则名/匹配文本），再构造 `DetailWorker(result, gen)`，`worker.done.connect(...)`，`worker.start()`。
- 新增 `_on_detail_done(model, generation)`：清理 worker 引用；`generation != self._detail_generation` 则丢弃；否则替换缓存 + emit `detailHitsModelChanged`。
- 新增 `_cancel_detail_worker()`（`contextlib.suppress` disconnect + `quit()` + `wait(500)` + 置 None）与非阻塞 `_cleanup_detail_worker()`（disconnect + `deleteLater` + 置 None）。
- 调用点接入（已核实 `selectedResultChanged.emit()`/`_selected_result_index=` 全部位置）：
  - [setSelectedResultIndex](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L931-L936)（行 935-936，索引真正变化分支内）末尾追加 `self._refresh_detail_hits()`——这是选中变化的主入口，`selectPrevResult`/`selectNextResult` 均经此。
  - 过滤/排序四处（[1017](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L1017)/[1028](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L1028)/[1045](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L1045)/[1057](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L1057)）：这些路径当越界会走 `setSelectedResultIndex(-1)`（已触发刷新）；未越界时选中的**底层 result 可能因过滤/排序而位移**，故在这四处 `selectedResultChanged.emit()` 之后同样追加 `self._refresh_detail_hits()` 保证详情与当前索引对应的 result 一致。`clearResultFilters`（[1064](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L1064)）同理追加。
  - 直接复位索引三处（[1247](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L1247)、[1319](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L1319)、[1432](file:///f:/Dev/fuscan/src/fuscan/gui/controllers/scan_controller.py#L1432)）绕过 `setSelectedResultIndex` 直接 `self._selected_result_index = -1`：在其后（1247 紧随 emit；1319/1432 处若无紧邻 emit 则在复位后）追加 `self._refresh_detail_hits()` 清空详情。
  - **实现要点**：`_refresh_detail_hits()` 设计为幂等——每次都 `_detail_generation += 1` 并取消旧 worker，重复调用只是多一次取消/重建，无副作用，故上述所有点无脑追加即可，无需精细判断"是否真的变化"。
  - `_cleanup_workers` 末尾接非阻塞 `_cleanup_detail_worker()`；`cleanup`/`quick_cancel` 接 cancel+quit+wait(200/500)+terminate 后备+deleteLater。`DetailWorker` 任务短无内部循环，无需 `cancel()` 方法，用 `quit()`/`terminate()` 即可。

**QML 零改动**：`detailHitsModel` 属性名与返回类型不变，仅换 notify 信号，QML 绑定自动跟随；已确认 QML 无 `Connections{onSelectedResultChanged}` 依赖该 model、无其他文件引用 `detailHitsModel`。
