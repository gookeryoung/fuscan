# 扫描速度提升实施计划

## 背景与目标

fuscan 的扫描分三阶段流水线：文件收集（walk）→ 文件筛选（filter）→ 文件解析（scan）。当前解析阶段的纯 Python 热点（charset-normalizer 全量编码检测、calamine 单元格遍历、正则匹配、olefile 读流）持有 GIL，只用 ThreadPoolExecutor 时无法真正并行 CPU 密集解析，是冷扫描（首次无缓存）大量文档时的主要耗时来源。

本计划目标：在**不引入进程池**、**不新增依赖**的前提下，聚焦**冷扫描-文档为主**场景，通过「减少 I/O、削减纯 Python CPU、优化引擎路径、调优调度节流」提升扫描速度；并**先建立可量化基线与回归对比工作流**，使每轮优化的提升可度量、回归可拦截。

## 约束

- 只用 ThreadPoolExecutor，不引入 ProcessPoolExecutor，不新增依赖。
- 提交前必须通过 `make check`（ruff lint+format、pyrefly 类型检查、pytest、覆盖率≥95%，当前 95.04% 不得降低）。
- CI 与 `make check` 默认 `-m "not slow and not gui_qml"`，所有基准/微基准保持 `@pytest.mark.slow`，不进功能门禁。
- 不改自动生成文件（resources_rc.py/_ui.py）；不擅自改工具链配置（pytest.ini/pyproject.toml/.coveragerc/pyrefly.toml）。
- 一条提交只含一个逻辑变更；文档与注释用中文。
- 凡改编码/提取/哈希路径，先补「优化前后输出等价」测试再改实现，保证正确性不退化。

## 分轮计划

### R1 建立性能基线与回归对比工作流（必做先行）

- **目标**：在优化前的 commit 上生成并提交官方基线，固化阶段级 + 微基准级双层对比工作流，不改工具链配置。
- **改动**：
  - 新建 `benchmarks/baselines/` 目录，提交两份基线：`scan_stage_baseline.json`（`fuscan benchmark <固定数据集> --rounds 5 --warmup 1 --save-baseline`）与 `perf_micro_baseline.json`（`pytest -m slow tests/test_perf_benchmark.py --benchmark-save` 后拷贝稳定副本）。
  - 固定数据集用 `generate_files(root, count, seed=42)` 生成到临时目录，基线 JSON 的 `meta` 记录文件数/seed/Python 版本/机器信息。
  - 新增 `benchmarks/make_baseline.py`：封装「造数→跑 benchmark→写 baselines」，保证可复现（`main()` 加 `# pragma: no cover`，位于 `benchmarks/` 不计入 `--cov=fuscan`）。
  - `.gitignore` 追加 `.benchmarks/`（防 pytest-benchmark 产物入库）。
- **量化验证**：同一 commit 连跑两次对比，阶段耗时波动应 <15%，证明基线稳定。
- **回归护栏**：固定 seed、warmup≥1、多轮取均值降低方差。
- **测试**：新增 `tests/test_make_baseline.py`（非 slow），仅测参数解析/meta 组装/路径拼接纯函数，mock 实际扫描，保覆盖率。

### R2 编码检测快路径扩展到小文件（低风险高收益，首推）

- **目标**：`_detect_encoding_from_header` 快检测从「仅 >10MB」扩展到全部文本，命中即跳过 charset-normalizer 全量分析。
- **改动**：[text.py `_decode`](file:///f:/Dev/fuscan/src/fuscan/extractors/text.py#L213-L244) 改为先对 `data[:_HEADER_SIZE]` 做头部快检测（BOM / UTF-8 严格 / GBK 严格），命中直接 decode 返回；仅未命中才回退 charset-normalizer。原回退链（charset-normalizer → utf-8/gbk → latin-1）不动。
- **量化验证**：`fuscan benchmark --baseline` 看 `extract` 阶段均值降幅；`TestHotPathBenchmark::test_extract_text_4kb --benchmark-compare` 看单文件延迟；`perf_profile.py` 看 extract 占比下降。
- **正确性红线**：先补对照测试——UTF-8/UTF-8-SIG/UTF-16/GBK/混合/含 BOM/纯 ASCII 样本，断言快路径输出与旧 charset-normalizer 路径等价（或关键子串如 password/AKIA 仍匹配）。若 GBK 快检测出现误判，收紧为仅 BOM + 纯 ASCII/UTF-8 走快路径、GBK 仍回退（零误判，收益略降）。
- **测试**：新增 `tests/test_extractors_encoding_fastpath.py`（参数化多编码 + 命中/未命中两分支）；原 `test_extractors.py` 编码用例全绿。

### R3 XLSX/calamine 单元格遍历热点削减（低风险高收益）

- **目标**：削减 PyO3 边界后逐行逐 cell 的纯 Python 开销。
- **改动**：[spreadsheet.py `_extract_calamine_workbook`](file:///f:/Dev/fuscan/src/fuscan/extractors/spreadsheet.py#L68-L93)——`isinstance(cell, str)` 快判避免对已是字符串的 cell 再调 `str()`；用列表推导 + `"\t".join(...)` 批量化替代逐 append；行列截断用切片替代计数分支；保留 `to_python()` 路径（空 sheet panic 规避）。
- **量化验证**：XLSX 占比高的数据集 `extract` 阶段降幅；`profile_self_scan.py` 确认 `_extract_calamine_workbook` 自耗时下降。
- **正确性红线**：输出格式（`--- 工作表: 名称 ---` 分隔、行内 `\t`、行间 `\n`）逐字节不变——先补「优化前后 XLSX 提取字符串完全相等」测试再改。XlsExtractor 共用后端一并回归。
- **测试**：`test_extractors.py` 增多工作表/空 sheet/超行超列截断输出等价用例。

### R4 并发调度与节流微优化（中等收益）

- **目标**：降低并发收割循环与进度节流的纯 Python 开销，不改并发模型。
- **改动**：[_pipeline_phase.py `_collect_concurrent_results`](file:///f:/Dev/fuscan/src/fuscan/scanner/_pipeline_phase.py#L226-L351)——仅在**无 UI 回调**（`_on_progress is None`，CLI/benchmark 纯吞吐）分支增大 `wait` 超时或改 `as_completed`，减少空转唤醒与 `_emit_progress` 调用；评估 `_scan_concurrent` 的 `seen_paths` 去重在 walk/filter 已去重前提下是否可条件跳过。GIL 让步 5ms 判据、取消加速路径不动。
- **量化验证**：`bench_scan.py` S2/S3 files/s 提升；`fuscan benchmark` 端到端 `mean_duration_ms` 下降。
- **正确性红线**：GUI 进度反馈路径（`_on_progress` 非空）行为完全不变，保「假卡死」修复不回退。
- **测试**：并发/取消用例全绿；新增无回调纯吞吐路径结果一致断言；`test_benchmark_20_rules_1000_files`、`test_incremental_throughput_ge_1000_files_per_sec` 不回退。

### R5 哈希与大文件 I/O 去重（中等收益）

- **目标**：确认并消除无缓存路径可能的二次读盘，优先不改哈希算法规避缓存兼容风险。
- **改动**：核对 [_helpers.py `default_extract_content_with_hash`](file:///f:/Dev/fuscan/src/fuscan/scanner/_helpers.py) 是否复用同一份 bytes 给 hash 与 extract；若存在二次 `read_bytes` 则消除。`_BIG_FILE_THRESHOLD` 用微基准复核最优切换点（仅测量，暂不改）。
- **量化验证**：`read_bytes` + `hash` 阶段总耗时下降（`fuscan benchmark` 阶段对比）。
- **正确性红线**：**不改哈希算法/阈值**，规避 `CACHE_COMPAT_VERSION` bump；若后续确需调阈值，单独一条提交并同步 bump 兼容版本（需用户确认）。
- **测试**：`test_hashes.py` 断言哈希稳定；新增读盘次数计数桩验证「hash 与 extract 复用同一 bytes」。

### R6 pdfium2 降级路径逐页循环优化（可选，优先级最低）

- **目标**：优化 [pdf.py `_extract_with_pdfium2`](file:///f:/Dev/fuscan/src/fuscan/extractors/pdf.py#L133-L165) 逐页循环（仅 Win7/无 pdf_oxide 时命中）。
- **改动**：复用 textpage 资源、减少 per-page cffi 往返，`"\n".join` 拼接。主路径 pdf_oxide 零影响。
- **量化验证**：CI 通常 pdf_oxide 与 pdfium 均在，收益难量化，故排最后并标可选。
- **正确性红线**：仅动降级分支，加密文档跳过逻辑不变。
- **测试**：有真实 PDF 样本则回归；无法造样本时仅做逻辑不变重构，不加吞吐断言。

### R7 回归复核、基线更新与文档同步（收尾）

- **目标**：复核 R2-R6 累计提升，更新优化后基线并保留 R1 原始基线作历史锚点，同步文档。
- **改动**：优化后 commit 重新 `--save-baseline` 另存为 `benchmarks/baselines/scan_stage_baseline_optimized.json`（保留原始基线）；README/开发文档记录各阶段与端到端实测降幅。
- **量化验证**：优化后 vs R1 原始基线逐阶段降幅表；`bench_scan.py` S1-S5 前后 files/s 对比。
- **正确性红线**：`make check` 全绿、覆盖率≥95.04%；`test_incremental_scan.py` ≥1000 files/s、`test_benchmark.py` ≥50/200 files/s 阈值全满足；所有 slow 基准 `--benchmark-compare` 无 mean>15% 回归。

- **必做先行**：R1（其余轮次依赖其对比锚点）。
- **首推低风险高收益**：R2、R3。

- **可选低优**：R6。
- **收尾**：R7。
