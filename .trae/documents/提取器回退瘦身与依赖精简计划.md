# 提取器回退瘦身与依赖精简计划

## Context（背景）

fuscan 是纯 Python 文件扫描器（PySide2 + QML）。经调查，提取器子包中存在两处「名义冗余」的多层回退路径，增加了代码复杂度与安装体积，但实际几乎不可达：

1. **DOCX/PPTX 的 python-docx / python-pptx 回退**：`_ooxml_xml.py` 硬依赖 lxml 作为主引擎；而 lxml 又是 ODF（`_odf_xml.py`）与 ODS（`spreadsheet.py`）路径的主引擎、且是 python-docx/pptx 的传递依赖——lxml 在运行时必然存在，因此 office.py/wps.py 里「lxml 不可用 → 回退 python-docx/pptx」的分支实际不可达，属死路径。
2. **PDF 的 pypdf 第三层兜底**：`pdf.py` 采用 pdf_oxide → pypdfium2 → pypdf 三层链，pypdf 是最慢兜底（T5），仅在「既无 pdf_oxide 又无 pypdfium2」的极端场景触发。

用户已授权：(a) 剪除 docx/pptx 冗余回退并将 python-docx/pptx 降级为 test-only 依赖；(b) 移除 pypdf 第三层兜底。另附带一项低风险纯代码清理：删除 config.py 中 QWidget 时代遗留、生产零读取的四个字段。

**预期结果**：提取器代码更简洁（DOCX/PPTX/PDF 引擎链层数减少），运行时依赖减少 3 个（python-docx、python-pptx、pypdf），config schema 更精简，`make check` 全套门禁通过（覆盖率 ≥ 95%）。lxml 保持为运行时依赖（ODF/ODS/OOXML 主引擎），不受影响。
