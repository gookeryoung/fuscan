# req-35 后续 10 轮迭代计划（iter-121 ~ iter-130）

## 概述

基于 iter-120 的性能基线与 CI 门禁完善，后续 10 轮迭代聚焦于：
功能扩展（导出/规则/凭证扫描）、性能优化（增量扫描/GUI 渲染/调度）、
用户体验（误报抑制/打包分发）、基础设施（文档/国际化）。

每轮迭代遵循 rule-01 五步闭环（计划 → 实现 → 测试 → 文档 → 验证），
全套门禁（ruff/pyrefly/pytest/coverage 95%）通过为验收硬性条件。

## iter-121 扫描结果导出格式扩展（SARIF）与流式写入优化

### 需求

- [x] 新增 SARIF 格式导出（GitHub Code Scanning 集成）
- [x] 大结果集（>10000 条）导出的流式写入（避免内存峰值）
- [x] 导出 Worker 重构：统一格式分发器，消除 JSON/CSV/HTML/SARIF 的重复逻辑
- [x] 配套测试覆盖 SARIF 格式与流式写入边界场景

### 验收标准

1. SARIF 导出可通过 GitHub Code Scanning 直接导入
2. 10000 条结果导出内存峰值 < 50MB（流式写入）
3. 导出格式分发器消除重复逻辑，新增格式仅需实现接口
4. 覆盖率不低于 95%，benchmark 验证导出性能无回归

## iter-122 规则系统增强（规则导入导出与规则模板）

- [x] GUI 规则管理页新增导入/导出按钮与模板选择对话框

2. 内置模板覆盖至少 5 类常见凭证场景
3. 不兼容规则导入时给出明确错误提示，不破坏现有规则集
4. 覆盖率不低于 95%

## iter-124 增量扫描与文件变更检测

### 需求

- [ ] 基于 mtime+hash 的增量扫描模式（仅扫描变更文件）

### 验收标准

4. 覆盖率不低于 95%，benchmark 佐证增量扫描性能收益
