# req-36 后续 10 轮迭代计划（iter-124 ~ iter-133）

## 概述

基于 iter-123 完成状态与最近用户实际反馈，制定 iter-124 ~ iter-133 共 10 轮迭代计划。

聚焦四个维度：
- **功能扩展**：增量扫描、误报抑制、凭证扫描增强、扫描目标管理
- **稳定性**：GUI null 防御、qrc 重建自动化
- **性能优化**：大结果集渲染、扫描调度、正则引擎
- **基础设施**：开发者文档、国际化、打包分发

每轮迭代遵循 rule-01 六步闭环（收集 → 计划 → 实现 → 测试 → 文档 → 验证），
全套门禁（ruff/pyrefly/pytest/coverage 95%）通过为验收硬性条件。

## iter-124 增量扫描与文件变更检测

### 需求

- [ ] 基于 mtime+hash 的增量扫描模式（仅扫描变更文件）
- [ ] 增量结果与历史全量结果的合并逻辑
- [ ] GUI 新增「增量扫描」选项（工作区卡片操作按钮）
- [ ] 增量扫描的缓存复用策略（未变更文件直接复用缓存结果）

### 验收标准

1. 增量扫描仅读取变更文件，未变更文件跳过 I/O
2. 增量结果合并后与全量扫描结果一致（同一文件集）
3. 增量扫描吞吐量 >= 1000 files/s（缓存命中场景）
4. 覆盖率不低于 95%，benchmark 佐证增量扫描性能收益

### 依赖

iter-123 扫描结果持久化（已完成）提供缓存基础

## iter-125 GUI 稳定性加固（PySide2 5.15 null 防御）

### 需求

- [ ] 全局 context property 统一声明类型化 property（Main.qml 补齐 WorkspaceController/ConfigController 等）
- [ ] qrc 重建自动化（pre-commit hook 或构建脚本集成，避免修改 QML 后忘记重建）
- [ ] QML 绑定 null 安全审计（所有 context property 访问点，消除潜在 null 引用）
- [ ] 取消/退出流程的模态遮罩统一（cancelPopup/exitPopup 模式复用到其他耗时操作）

### 验收标准

1. 所有 QML 文件中 context property 访问无 null TypeError
2. 修改 QML/SVG 后自动触发 qrc 重建，无需手动执行
3. 模态遮罩模式统一，所有耗时操作（扫描/取消/退出/导出）均有防重复操作保护
4. 覆盖率不低于 95%

### 背景

iter-123 后多次出现 QML null 错误（WorkspaceCard ConfigController、Main.qml WorkspaceController），
根因均为 context property 未声明类型化 property。需系统性修复而非逐个 patch。

## iter-126 GUI 性能优化（大结果集渲染）

### 需求

- [ ] 结果列表虚拟化渲染（支持 10000+ 条结果流畅滚动）
- [ ] 结果分页加载（滚动到底部自动加载下一页）
- [ ] 统计图表渲染优化（缓存计算结果，避免重复绘制）
- [ ] 结果列表搜索/过滤性能优化（防抖 + 索引）

### 验收标准

1. 10000 条结果滚动帧率 >= 30fps（不卡顿）
2. 搜索/过滤响应时间 < 300ms（防抖后）
3. 图表切换无白屏闪烁
4. 覆盖率不低于 95%

## iter-127 误报抑制与规则白名单

- [ ] 文件级/路径级白名单（误报标记后不再报告）
- [ ] 规则例外配置（特定文件/路径跳过特定规则）
- [ ] 白名单持久化到 ~/.fuscan/whitelist.json

2. 规则例外支持 glob 路径模式匹配
3. 白名单可导入/导出（JSON 格式）
4. 覆盖率不低于 95%

## iter-128 扫描调度与任务队列优化

### 需求

- [ ] 多工作区并行扫描调度（资源限制下的任务队列）
- [ ] 扫描任务优先级与取消机制完善
- [ ] 后台扫描与 GUI 操作互不阻塞（线程隔离优化）
- [ ] 扫描进度聚合（多工作区同时扫描时的总进度）

### 验收标准

1. 多工作区并行扫描时 CPU 利用率合理（不抢占总线程）
2. 扫描中 GUI 操作（切换页面/编辑规则）无阻塞
3. 任务取消在 1s 内生效
4. 覆盖率不低于 95%

## iter-129 凭证扫描增强（正则引擎与熵检测）

### 需求

- [ ] 高熵字符串检测（Base64/Hex 密钥泄漏，Shannon 熵计算）
- [ ] 正则规则引擎优化（预编译缓存 + 批量匹配）
- [ ] 内置凭证模式扩展（API key/private key/JWT/token 模式）

### 验收标准

1. 高熵字符串检测识别 Base64/Hex 密钥，误报率 < 10%
2. 正则匹配性能提升 >= 2x（预编译缓存收益）
3. 内置凭证模式覆盖至少 10 类常见密钥格式
4. 覆盖率不低于 95%，benchmark 佐证正则引擎性能提升

## iter-130 扫描目标管理增强

### 需求

- [ ] 大型软件清单动态扩展（用户自定义忽略目录分类，不限于预设清单）
- [ ] 扫描目标预设（开发目录/文档目录/全盘扫描等快捷方案）
- [ ] 扫描目标历史记录（快速选择最近扫描过的路径）
- [ ] 扫描范围可视化（树形展示将扫描的目录与跳过的目录）

### 验收标准

1. 用户可自定义忽略目录分类（添加/编辑/删除），与预设分类统一管理
2. 扫描目标预设覆盖至少 5 种常见场景
3. 扫描目标历史记录持久化，重启后可用
4. 覆盖率不低于 95%

### 背景

iter-124 前用户多次反馈大型软件清单扩展需求（JetBrains/FreeCAD 等），
需将静态清单扩展为用户可自定义的动态分类管理。

## 优先级与依赖关系

```
iter-123 (用户反馈修复) ─→ iter-124 (增量扫描) ─→ iter-128 (调度优化)
                         ─→ iter-125 (GUI 稳定性) ─→ iter-126 (GUI 性能) ─→ iter-132 (国际化)
iter-124 (增量扫描) ─→ iter-127 (误报抑制)
iter-125 (GUI 稳定性) ─→ iter-130 (扫描目标管理)
iter-129 (凭证扫描) ─→ iter-131 (文档) ─→ iter-133 (打包分发)
```

- iter-124（增量扫描）为最高优先级，用户已等待多轮

- iter-126~133 可根据 iter-124/125 完成情况灵活调整
- iter-131/133 相对独立，可灵活调整
